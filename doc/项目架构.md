# WanAndroid 项目架构

本文档系统说明 WanAndroid 项目的整体架构、模块划分、分层设计与关键技术实现，供开发者快速建立全局认知。

## 1. 总体架构

### 1.1 架构风格

WanAndroid 采用 **MVVM + Clean Architecture 风格**，但未单独抽出 domain 用例层——用例逻辑直接并入 Repository，ViewModel 直接调用 Repository。

```text
┌─────────────────────────────────────────────────────────┐
│  Presentation 层（UI）                                  │
│  ├─ View System：AppCompatActivity + ViewBinding + XML │
│  └─ Compose：ComponentActivity + WanAndroidTheme       │
└────────────────────────┬────────────────────────────────┘
                         │ 调用
┌────────────────────────▼────────────────────────────────┐
│  Data 层                                                │
│  ├─ WanRepository（object 单例，单一数据源）            │
│  ├─ Remote：RetrofitClient + 4 个 Retrofit Service       │
│  ├─ Cache：MemoryCache + DiskCache（CompositeCache）    │
│  └─ Local：DataStore / SharedPreferences / LitePal      │
└─────────────────────────────────────────────────────────┘
```

### 1.2 技术栈

| 维度 | 选型 |
|---|---|
| 语言 | Kotlin 2.1.21 |
| 构建 | Gradle 8.13+（Kotlin DSL 与 Groovy DSL 混用），AGP 8.13.2 |
| JDK | 17（工具链），输出字节码 1.8 |
| 最低 SDK | 21 |
| 目标 / 编译 SDK | 36 |
| UI | View System（主体）+ Jetpack Compose（并行） |
| 架构组件 | Lifecycle + LiveData + ViewModel + Paging + Navigation |
| 网络 | OkHttp 4.12 + Retrofit 2.12 + Coroutine + PersistentCookieJar |
| 缓存 | 自研三级缓存（Memory + Disk + Network） |
| 图片 | Glide 4.16 + Coil 2.4（Compose） |
| 存储 | DataStore（实际使用）+ LitePal（未使用）+ Room（未使用）+ SharedPreferences |
| 消息总线 | LiveEventBus |

### 2.3 `:module_debugtools` 模块

独立 Android Library，包名 `com.zjmok.debugtools`，封装 BaseUrl 修改 UI + 数据层 + 拦截器，可跨项目复用。模块**不提供** Service，悬浮窗主体由 app 自行管理。

```text
module_debugtools/src/
├── main/
│   ├── java/com/zjmok/debugtools/
│   │   ├── DebugBaseUrl.kt          # BaseUrl 持久化数据层（SharedPreferences "float_window_prefs"）
│   │   └── DebugBaseUrlView.kt       # 自定义 LinearLayout（BaseUrl 表单 + 预设切换）
│   └── res/layout/
│       └── debug_base_url_view.xml   # merge 标签：BaseUrl 表单 + 预设按钮
├── debug/
│   └── java/com/zjmok/debugtools/
│       └── BaseUrlInterceptor.kt     # 真实实现，读取 DebugBaseUrl.currentUrl 替换请求 URL
└── release/
    └── java/com/zjmok/debugtools/
        └── BaseUrlInterceptor.kt     # 占位空实现，直接 chain.proceed()
```

**变体传递**：Android Gradle Plugin 自动选择——app 的 debug 变体使用模块的 debug 变体（真实拦截器）；app 的 release 变体使用模块的 release 变体（占位实现）。

**集成方式**（3 步）：

1. `app/build.gradle` 添加 `implementation project(":module_debugtools")`
2. `RetrofitClient` 中 `import com.zjmok.debugtools.BaseUrlInterceptor` 并 `.addInterceptor(BaseUrlInterceptor())`
3. `App.onCreate()` 调用 `DebugBaseUrl.init(this, AppConst.BASE_URL)`

**可选**：app 的 debug 源集悬浮窗布局中通过 `<com.zjmok.debugtools.DebugBaseUrlView android:id="@+id/base_url_view" .../>` 引入 BaseUrl 修改 UI，悬浮窗 Service 中调用 `binding.baseUrlView.refreshViews()` 刷新表单即可，无需管理 BaseUrl 持久化逻辑。

## 3. 数据层

### 3.1 WanRepository —— 单一数据源

文件：`app/src/main/java/org/example/wan/android/data/repository/WanRepository.kt`

- 使用 Kotlin `object` 单例，由 `App.onCreate()` 调用 `WanRepository.init(this)` 初始化（初始化 `DiskCache` 与 `CompositeCache`）
- 持有四个 Retrofit Service，全部通过 `RetrofitClient.create(...)` 懒加载：
  - `apiService`（WanService）：Banner、首页、项目、公众号、搜索、问答
  - `userService`（UserService）：注册、登录、登出、用户信息
  - `squareService`（SquareService）：广场
  - `likeService`（LikeService）：收藏
- **核心方法**：私有 `suspend inline fun <T> getWithCache(cacheKey, expireTime, fetch)` 实现三级缓存编排

#### 缓存过期时间常量

| 接口类别 | 过期时间 |
|---|---|
| Banner | 30 分钟 |
| HomeTopList | 30 分钟 |
| ProjectTree / WxArticleTree | 24 小时 |
| ProjectList / WxArticleList | 10 分钟 |

### 3.2 网络层

文件：`app/src/main/java/org/example/wan/android/data/remote/RetrofitClient.kt`

#### OkHttp 配置

- **Cookie**：`PersistentCookieJar` + `SharedPrefsCookiePersistor`，持久化到 SharedPreferences
- **超时**：connect / write / read 均 10 秒
- **重试**：`retryOnConnectionFailure(true)`
- **HTTP 缓存**：路径 `AppConst.okhttpCachePath`，容量 64 MB

#### 拦截器链（按添加顺序）

1. `BaseUrlInterceptor`（来自 `:module_debugtools` 模块：debug 变体真实实现运行时可改 BaseUrl；release 变体为占位空实现直接放行请求）
2. `LoggingInterceptor`
3. `CacheInterceptor`（HTTP 层缓存，`max-age=1 天` / 离线 `max-stale=30 天`）
4. `HeaderInterceptor`（已定义但当前未启用）

#### Retrofit 配置

- baseUrl = `AppConst.BASE_URL = "https://www.wanandroid.com/"`
- 添加 `ScalarsConverterFactory` + `GsonConverterFactory`（Gson 配置 `disableHtmlEscaping`）
- 所有 Service 方法返回 `suspend fun ... : ApiResult<T>`

#### ApiResult 与异常体系

- `ApiResult<T>`：泛型 data class，字段 `errorCode / errorMsg / data`
- `apiData()` 扩展：`errorCode == 0` 返回 data，否则抛出 `ApiException`
- `ApiException`：自定义异常，`errorCode = -1001` 表示未登录
- `BaseViewModel.handleError()` 按 errorCode 分流处理

### 3.3 三级缓存实现

位于 `app/src/main/java/org/example/wan/android/data/local/cache/`。

```text
┌─────────────────────────────────────────────────────┐
│  WanRepository.getWithCache(cacheKey, fetch)        │
└────────────────────────┬────────────────────────────┘
                         │
        ┌────────────────┴────────────────┐
        │ 缓存禁用？                    │
        └────────────────┬────────────────┘
                是 ───────┼─────── 否
                        │       │
                Network  │       ▼
                        │   ┌──────────────────────┐
                        │   │ CompositeCache.get() │
                        │   └──────────┬───────────┘
                        │              │
                        │      命中 ───┼─── 未命中
                        │       │      │
                        │       ▼      ▼
                        │   立即返回   Network
                        │   + 异步刷新  → 写回两层缓存
                        │              │
                        └──────────────┴──── 返回
```

#### 各层职责

| 文件 | 角色 | 实现 |
|---|---|---|
| `RequestCache.kt` | 接口 | `get / put / clear / clearExpired` 全部 suspend |
| `CacheItem.kt` | 数据结构 | `data: String` + `timestamp` + `expireTime`，`isExpired` 计算属性 |
| `MemoryCache.kt` | L1 内存缓存 | `mutableMapOf` + `Mutex` 协程锁，进程内有效 |
| `DiskCache.kt` | L2 磁盘缓存 | object 单例，路径 `cacheDir/network_cache/`，文件 IO + Mutex + `Dispatchers.IO` |
| `CompositeCache.kt` | 组合模式 | 读：Memory → Disk（命中后同步到 Memory）；写：同时写入两层 |
| `CacheKeyGenerator.kt` | 键生成 | URL + 排序后的 params → MD5 |

**注意**：所谓「三级缓存」实际是「Memory + Disk 两层 + Network 第三级」——Network 不在 `RequestCache` 接口里，由 `WanRepository.getWithCache` 编排。

详见 [三级缓存架构设计与实现分析.md](三级缓存架构设计与实现分析.md)。

### 3.4 本地存储

| 方案 | 状态 | 用途 |
|---|---|---|

## 5. 依赖注入

### 5.1 手动 DI（无 Hilt / Koin）

- **单例 object**：`App`、`App.INSTANCE`、`WanRepository`、`RetrofitClient`、`DiskCache`、`UtilLib`
- **App 持有共享对象**：
  - `appViewModel: AppViewModel`
  - `appScope: CoroutineScope`（Dispatchers.Default + SupervisorJob）
  - `dataStore`（Preferences DataStore）

### 7.1 Splash Screen（仿 bilibili 无缝衔接）

文件：`app/src/main/java/org/example/wan/android/presentation/feature/splash/SplashActivity.kt`

- `setKeepOnScreenCondition { isShowSplash }` 控制系统 SplashScreen 保持显示 1 秒
- `setOnExitAnimationListener` 执行 250ms alpha 渐隐后：

  3. `preRequest()`：提前调用 `WanRepository.getBanner()` 预热网络
  4. `initView`：1 秒倒计时（Flow 实现），可点跳过
  5. 倒计时结束 → `start<MainActivity>` 并 `finish()`

### 7.2 Scheme / DeepLink 处理

文件：`app/src/main/java/org/example/wan/android/presentation/feature/web/SchemeActivity.kt`

`AndroidManifest.xml` 声明：

### 7.3 WebView 实现

文件：`app/src/main/java/org/example/wan/android/presentation/feature/web/WebActivity.kt`

#### 防内存泄漏

- WebView 用 `WebView(App.INSTANCE)` 构造（不绑定 Activity Context），通过 `binding.layoutWebViewContainer.addView(it)` 加到容器
- `onDestroy` 顺序：`webView.stopLoading()` → `webView.destroy()` → `binding.layoutWebViewContainer.removeAllViews()` → `super.onDestroy()`

#### WebSettings

- JS 开启
- `useWideViewPort` + `SINGLE_COLUMN` + `loadWithOverviewMode`
- `setSupportZoom` + `builtInZoomControls` + 隐藏原生缩放控件
- `cacheMode = LOAD_CACHE_ELSE_NETWORK`
- `domStorageEnabled` + `databaseEnabled`（微信文章需要）
- UTF-8 编码

#### 客户端

- `WebChromeClient.onProgressChanged`：更新顶部进度条，`onReceivedTitle` 更新标题并通过 `WebPageRepository.updateWebPage` 持久化浏览历史
- `WebViewClient.shouldOverrideUrlLoading`：`http`/`https` 用 webView 自身加载，其它 scheme 走 `startBrowser`

#### 返回键

`onBackPressedDispatcher.addCallback` 优先 `webView.goBack()`，无法回退时禁用 callback 调用默认返回。

#### 菜单功能

`R.menu.menu_web_activity`：刷新、收藏（搜索现有 → XPopup 确认对话框 → 输入框 → `updateWebPage`）、复制 URL、分享（`ACTION_SEND`）、浏览器（同时演示 `getHttpHttpsApps` / `getAllHttpApps`）。

### 10.3 BaseUrl 动态切换

`BaseUrlInterceptor` 由 `:module_debugtools` 模块提供：

- **debug 变体**：模块的 `src/debug/` 提供真实实现，读取 `DebugBaseUrl.currentUrl` 替换请求 URL
- **release 变体**：模块的 `src/release/` 提供占位空实现，直接放行请求

变体传递由 Android Gradle Plugin 自动处理：app 的 debug 变体使用模块的 debug 变体；app 的 release 变体使用模块的 release 变体。app 无需在 `src/placeholders/` 维护占位代码。

## 11. 开发约定速查

| 项目 | 约定 |
|---|---|
| 单例 | Kotlin `object`，避免构造参数 |
| ViewModel 获取 | `module_utils` 的 `getViewModel()` 扩展 |
| 日志 | 项目统一 `log()` / `logd()` / `loge()` / `logi()`，禁止 `android.util.Log` |
| 资源目录 | 按功能归入 `res-splash` / `res-setting` / `res-language`，不堆在 `res/` |
| 仓库声明 | 仅 `settings.gradle`，模块 build.gradle 不可加 `repositories` |
| Git 命令 | 必须用 `providers.exec { ... }`，禁用 `executeCmd`（破坏 configuration-cache） |
| WebView | 用 `WebView(App.INSTANCE)` 构造，onDestroy 按规范顺序 |
| Activity / Fragment | 必须在 `AndroidManifest.xml` 注册 |
| 新增页面 | 继承对应基类（`VVMBaseActivity` / `VVMBaseFragment`），不直接继承系统类 |
| 数据存储 | 优先 DataStore，Room 依赖已声明但未启用 |
| Compose | 在 `presentation/compose/` 下新增，使用 `WanAndroidTheme` |
